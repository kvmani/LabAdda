# Chat, threads and private sharing

Each workspace has its own chat. Organization access flows upward; a division
role does not reveal child sections. Private groups have only explicitly selected
members, and administrators do not automatically see their content.

Choose **Open thread** on a message or reply. A thread belongs to its original
message's workspace. Refresh discussion to load newer replies while keeping your
unsent draft. Older replies are paged. Replies also remain in the main stream;
unread state is per workspace. **Load earlier messages** pauses replacement of that
page by live activity. **Return to latest messages** resumes the recent stream.

Attach PDF, PNG or JPEG files in a message/reply using **Attach files**. Uploads
use the same size/count safeguards as other content. Wait for unresolved uploads;
if an upload reply is lost, use **Check upload result** or **Retry same file**.
When sending is unconfirmed, the original text, thread and selected files are
frozen; **Retry same message** recovers that message without duplicate attachments.
Keep the view open: files/drafts/retry state do not survive navigation or reload.
Dismissing unresolved uploads does not delete stored data; check storage first.

**Private conversation** opens group creation with one colleague and then its chat.
This is a private group with normal membership management, not a separate direct-
message system. Later membership changes explicitly determine who can see its
history. Uncertain group creation blocks blind resubmission and refreshes My groups
so you can inspect the result. Private messages/files do not become visible to a
section, division, or administrator unless they have actual group membership.

File links/previews check current workspace access. Removing a colleague stops
new chat/file access; bytes already downloaded remain with that colleague.
Sharing a text summary or creating a task does not automatically copy attachments.
