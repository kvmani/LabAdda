## Referenced-file inspection slice

Schema 0008 adds operator-only non-destructive inspection receipts. `labadda inspect-storage` has file/byte limits and cooperative scan-time checks, fixed selected metadata rows, size/hash verification for originals, separate readable-preview bytes and capped diagnostic samples. Missing, modified, unsafe or unavailable files produce explicit issue codes; budget exhaustion remains partial. It does not enumerate orphan files, repair counters, delete blobs or authorize enforcement. A live scan can race changes; previews have no stored expected integrity digest, so their integrity remains unverified. The scan time budget cannot bound blocking filesystem/database I/O. ## Upload request receipts and replay

Schema 0012 adds optional owner-scoped upload keys bound to measured bytes and submitted metadata. Pending receipt/reservation creation is durable before storage; completion, Asset insertion and reservation removal are atomic. Identical completed requests return the original file without extra bytes or quota charges. Conflicting intent, pending work, failed/expired attempts and deleted results have distinct stable errors. Owner-only status rechecks current content access; administrators, siblings and board-only sessions cannot use receipts as an access grant. Request identity expires after 24 hours, with lazy per-user cleanup on subsequent admission. Restore invalidates copied attempts alongside reservations.

Independent review reproduced a cleanup deadlock caused by receipt and expired-reservation lock inversion. Failure release now serializes through the same user row before locking the reservation/receipt, without requiring the failed worker's session to remain valid. A concurrent regression pauses failure release with its receipt locked, waits until PostgreSQL confirms another admission is blocked, then verifies both finish. User deactivation/revocation still cannot block necessary cleanup solely because authorization expired.

Validation: **250 backend tests**, real PostgreSQL recovery, migration drift, **11 frontend tests**, typecheck and production build passed serially. ## File-picker recovery controls

The noticeboard and desktop board now retain bounded, in-memory upload attempts with a request key and the exact selected File. Users explicitly check a receipt or retry the same request; there is no automatic write retry. Pending attachments block posting, board images serialize through one unresolved attempt, and failed/expired/inaccessible results cannot silently start over. Already-used assets are not placed/attached again. The client stops retrying before the server's 24-hour identity window ends. Dismissing does not delete a stored file. Navigation, reload and sign-out discard these in-memory controls; persistent recovery remains future work.

Independent review caught a truncated-success-body case: headers may arrive after commit while JSON parsing fails. The transport now reports an uncertain response rather than a parser error or false success; same-key recovery remains available. **31 frontend tests**, typecheck and build passed. **24 Chromium root/prefix checks** passed across actual noticeboard and board inputs, post-commit response loss/truncation, current-view check/retry, single charging, durable attachments and mobile controls. ## Text and whiteboard logical charges

Schema 0014 adds a per-item logical charge ledger with two versioned rules: `utf8-text-v1` for posts, replies, chat and notes, and `board-object-json-v1` for each live whiteboard object. Database triggers keep text charges in the same transaction as every write, including fixtures, recovery and direct SQL. The migration backfills existing text. Board writers charge each operation atomically. A board's first write after the migration recharges its whole current state, and restore recharges the new epoch. Boards with older history stay explicitly unknown, reported as a lower bound, until a write or reconciliation completes them. Attribution follows the stable contributor, including restored objects and panel sessions. Removed posts whose bodies remain stored are charged as `removed`, not dropped.

`GET /usage` and `/admin/usage` report charges by type and state, with board coverage; user, admin and observer web views show them without content. `labadda reconcile-charges` is a bounded host-operator dry run or digest-confirmed apply that corrects ledger rows only. It detects missing, orphaned and stale (bytes, state, attribution, method) charges, uses keyset cursors and item/board/object/time budgets, and binds the observed drift classes into the plan digest so renewed drift invalidates an earlier review. See the [procedure](CHARGE-RECONCILIATION.md).

Self-review before commit found two issues, both fixed with regressions: a stale plan was accepted when renewed drift needed the same correction, and receipts would have echoed client-chosen board object IDs (now short digests). Browser on fresh stacks at root and prefix: **22 content-charge checks** ([evidence](evidence/content-charges/README.md)), **18 governance** and **69 collaboration/touch** checks. Hosted CI completion is not claimed, and the development/research instances were not migrated in this session.

## Physical database storage

## Site capacity proposals and observation-only preview

Schema 0015 accepts version-two immutable observation proposals alongside unchanged version-one history. Version two adds an optional positive site asset budget and bounded filesystem reserve floor/percentage. The existing reason, revision conflict, locked authority and audit rules still govern saving. Downgrade refuses populated version-two history. No proposed value changes current original-only pilot admission, reserves storage or permits deletion.

An admin-only, CSRF-protected web preview includes tracked originals, known previews and pending originals as a lower bound; budget headroom is explicitly an upper bound. Filesystem reserve uses integer ceiling and the greater of floor/percentage. Missing/invalid capacity remains unknown, and shortfalls are labeled. Previews always remain incomplete because unknown previews, unreferenced/other files, temporary/system storage and shared filesystem attribution remain unresolved. Measurements are independently timestamped; no future growth prediction or activation approval is implied. The result requires refreshed admin/session authority and a sanitized profile-digest audit. Operational readers and panel sessions are denied.

The form clears previews on every profile edit and observation refresh and ignores late results for changed inputs. Version-one capacity fields display Not recorded. Proposal/account/workspace tables now scroll accessibly on phones; browser testing found and fixed overflow and verified keyboard horizontal scrolling. Existing proposals are never rewritten.
