# Rollout review — 18 November 2026

Reviewed upstream `3def7d8` (0.1.0-beta), including the ZIP rollout, PM co-hosting, live alerts,
and the recovered [17 November fixes](review-2026-11-17.md). Preserve the published 0048
and 0049 migrations and manual-only GitHub Actions. No deployment or environment publication.

- The ZIP build checks configured mirrors before installing packages, uses a unique scratch
  directory, and verifies the copied source against its expected digest.
- Site settings are validated as data for operator commands. Failed nginx changes restore the
  shared site's previous include, snippet and map. The isolated restore path checks loopback
  readiness without trying to resume an absent proxy route.
- Plain-HTTP actions generate valid UUIDs using browser randomness. Native Windows uses the
  selector event loop and reports unavailable inode measurements honestly.
- Site analytics observe the existing aggregate privacy floor. Join decisions serialize and
  recheck identity, affiliation and authority. A public submission cannot discover staff accounts.
- Home retains drafts, rejects stale access-scoped responses and confirms task completion before
  offering revision-safe undo. Calendar reminder cards track their workspace's current access.

The code can be exercised with disposable PostgreSQL and nginx on a development machine.
Before admitting real users, rehearse ZIP install, backup, restore, upgrade and restart on the
actual Ubuntu host using the office mirrors and service account. Test PM and LabAdda together,
check the intended proxy route and confirm access from a second client. Plain HTTP exposes
credentials and data in transit. Use trusted HTTPS for production use with real staff data.
Native Windows HTTPS and CA trust require a Windows smoke test. See the
[office deployment guide](../deployment/README.md) and [Windows pilot guide](../WINDOWS-PILOT.md).
