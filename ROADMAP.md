## Collaborative groups (S2.1)

Users create flat, invite-only workspaces with chosen colleagues. Groups get every section feature (noticeboard, whiteboard, chat, search, reminders, notifications) but have no parent, no inheritance and no hierarchy controls. The creator is the first steward. Stewards manage members, roles, name, posting policy and archive. Members can leave, and the last steward is protected. The feature shipped with P2 and reuses the shared policy module, so P3 and P4 work (sockets, board-only sessions, snapshots) covers groups automatically. Follow-ups for P5 are an optional invitation-acceptance step, group discovery or join requests if the site wants them, and group retention rules once the site sets content retention.

## P3 remaining work

1. Publish a selected board region as an immutable snapshot at a committed revision. Default to the same workspace. A parent destination requires fresh read/write checks, a preview and confirmation naming the broader audience. The destination owns the copy (T09).
2. Embed approved raster images on the board, reusing the attachment validation and preview pipeline.
3. Compact board history into durable snapshots, and fall back to the snapshot on reconnect when replay has been compacted.
4. Add a restart-recovery test that kills the server between commit and fanout and shows that clients converge through replay (T08). Add an explicit socket revocation test under concurrent live traffic (T10).
5. Run a multi-session drawing soak (8 drawers) to prepare for the P4 performance rehearsal.
