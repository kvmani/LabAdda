## What this is for

Use this when a change should start on a particular day, for example a transfer at the start of a new term or a retirement on someone's last day. Nothing changes until that day.

## Before you start

You need to be a site administrator. Pick a day after today, within five years. Adding a person and reinstating a person cannot be scheduled, because their one-time activation code is shown only on the screen of the person who applies the change.

## Steps

1. Start the change as usual, for example choose **Transfer** on a person's record, and fill in the details.
2. On the review step, under **When should this happen?** choose **At the start of a later day**, then choose the **Day it takes effect**.
3. Read the plan. It shows what will happen on that day.
4. Type the **Reason for this change** and choose **Schedule change**, then choose **Done**.

To see what is waiting, open **People**. The **Scheduled changes** list shows every change, and a person's record shows the ones about them. Choose **Cancel this change**, give a reason, and nothing will be applied.

## What happens next

At the start of the day, LabAdda checks the change again. If it is still exactly what you reviewed, it is applied and recorded as yours, with your reason. If anything it depends on has changed, nothing is applied. The change is marked **Needs review** with a plain reason and appears on the **Needs attention** list. Choose **Dismiss this change**, then make the change again from the start if it is still wanted.

## If something goes wrong

- "Choose a day after today and within five years". Pick a later day.
- "This change issues an activation code, so it cannot be scheduled". Make this change now.
- "Needs review". Read the reason shown, then dismiss the change and schedule it again.
